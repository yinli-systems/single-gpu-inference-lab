# Full model and lifecycle protocol

Freeze before testing. Use all 36 layers of cached Qwen3-4B-Instruct-2507, no weight substitution or pruning. Native SGLang HTTP token-ID streaming API (tokenizer init omitted, explicitly not text frontend timing). Source-bound 0.7 official, off, cap and wide overlays. Each server is a fresh subprocess and only its owned process group is terminated. Localhost port only. All startup/JIT/capture/warmup excluded and reported separately. Model weight hashes captured once outside benchmark; configs and complete index included.

Before serving, run paged fixed-shape graphs through four KV-length transitions, two independent streams/workspaces, disjoint and shared physical pages, FP16/BF16, FP32 sampled reference and full pristine output/LSE comparison. No concurrent mutation of a shared graph or workspace. This qualifies those explicit lifetimes, not arbitrary external concurrent calls.

Bounded smoke validates real HTTP streaming, fixed requested token count and source/launch path. Formal test: three fresh servers per arm with balanced arm order, 3 repetitions of closed-loop prefill/decode/mixed workloads, 16 requests/workload, specified c4/c8, output lengths32/128/64, fixed client inputs. Measure client throughput, TTFT, TPOT, tails and goodput. Profile a separate post-measurement request through documented start/stop endpoints; failure or zero eligible hits prevents an active-optimization claim. Never use profiled duration as performance. Native token IDs are checked request-by-request across arms; any output mismatch prevents apples-to-apples serving performance promotion. Wide is exploratory, not automatically a numerically identical kernel.

No policy trained on confirmation data. Preserve startup, qualification, numerical and runtime failures. Unsupported dependencies or failures are an unqualified path, not a negative throughput sample or reason to silently replace model/runtime. The cap/overhead variants are fixed before observation; do not call an exact-witness gain a serving gain. Headroom for concurrency/resource changes must be evaluated independently.
