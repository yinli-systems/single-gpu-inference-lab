# Resource generalization protocol — frozen before new observations

Primary: resource-only cap, NOT a reordering heuristic. The candidate preserves request order and the mathematical/device source. It raises 48-KiB launch reservation to 64 KiB for compatible D128, 16-bit, CTA128, unsplit, softmax kernels on 100-KiB/SM devices. Other cases retain native. No exact query-length or request-count rule. Secondary wide-KV uses the extra resource budget for a larger compile-time KV tile; numerical equivalence must be measured separately.

Variants are private, process-immutable copies of the official 0.7.0 wheel, with exact header hashes. No shared environment modifications, no live environment flag, no hidden per-request timing or learned selector. Off variant controls source packaging/allowed-maximum effects. Native and candidates use unchanged automatic plans; the cap is not applied to split-KV calls.

Frozen geometry sets: three qualification/exposed entries, 16 development families, 24 new confirmation families with disjoint request-count families. Both dtypes, ragged and paged NHD, auto and forced-unsplit. Eight balanced same-work A/A blocks per mode and separate one-call/16-call CUDA Graph regimes. One physical GPU within each allocation, three fresh processes per mode with cyclic mode order. Kernel comparisons across modes have independent blocks; do not label them matched samples. Keep geometry families together and do not reuse development to claim unseen validation. Off is an additional comparator, not a candidate selected from performance.

Qualification: exact full outputs/LSE for cap and off versus pristine on fixed seeded tensors; independent FP32 selected rows for all modes; wide also full-output allclose against saved pristine outputs. Seeds/data bindings must agree. Numerical failures stop affected paths before performance interpretation. NaN overwrite and graph/eager parity required. Numerical error statistics and all failures retained. Large oracle calculations excluded from timing.

Performance: include plan+one/16 actual calls and record run-only separately. Timing excludes import/JIT/capture/reference I/O, all reported explicitly. Source and model hash coverage, setup costs, path hit/miss rates, per-shape worst case, A/A resolution, and no-op controls required. Primary statistical inference uses process clusters; conditional on frozen cases and physical devices. No multiple-testing or universal safety guarantee. A/A 90% interval must fit [1/1.005,1.005] for 1% claims. Any strong fresh slowdown or no mean advantage prevents default promotion; no post-hoc rule fit to confirmation.

Serving integration is isolated and default-off: qualify paged, graph replay with repeated planning, independent streams and poisoned outputs first. Then run complete model via a real engine and HTTP streaming, with pristine/on parity, actual eligible-launch proof, identical workloads, explicit warmup, independent process repeats, total-client throughput, TTFT/TPOT/tails and SLO-goodput. Zero-hit paths are not performance proof. If prerequisites or resources fail, preserve failure and mark serving unqualified rather than fabricate an achieved speedup.

Upstream: patch-source applicability and tests are distinct from accepted/merged upstream work. Increasing dynamic shared memory as an occupancy diagnostic is established in NVIDIA's Best Practices Guide. Neither that technique nor a policy label is claimed new. Target contribution is measured applicability, a low-overhead implementation and verified caller coverage.
