# Finite complete qualification controller

`complete_campaign.py` executes the user-authorized remaining qualification stages in order. It uses the existing independently source-bound controllers, preserves every child result and raw archive, and never repeats a failed stage. Preparation does not generate fresh cases or authorize model launches.

The initial two exposed public cases use immutable 0a5c735 source, exact original measurement/contract bytes, private caches, the original nine-process/24-cell recipe and initial 12-hour allocations. The original c6879fb campaign remains immutable HOLD. Both complete new GPU analyses and full archive must PASS before the controller creates a formal source/manifest binding. Then dual90 smoke, dev2, new10 canary, original48 release and original12 stress run under separate stage authorization and all unchanged floors. A complete formal archive PASS is required before any HTTP initializer. Four complete Qwen models, two GPU families, functional/performance/parity and three paired allocations require 72 real allocations and 24 independent verdicts. The full raw HTTP archive retains every failed request and managed decision.

The workflow has a finite 30-day deadline, child kernel/HTTP controllers each have their existing 14-day bounds, and failed child allocations retain their fixed 12h/8h limits. No known allocation is archived while active. Submission outcomes that are unknown block archive and all successors; intent receipts prevent accidental duplicate dispatch. No resampling, trimming, changed control population or relaxed floor is allowed. A source mismatch halts before the next stage.

A final kernel/HTTP PASS remains `KERNEL_HTTP_PASS_HISTORY_AND_UPSTREAM_REVIEW_REQUIRED`. It cannot reconstruct missing original pre-divergence states, close historical 2/432 by inference, enable defaults or publish upstream PRs. All historical/default/serving-promotion flags stay false. Real Resource Graph metadata-update parity is still a separate unsupported-boundary question; Native Graph correctness does not qualify Resource Graph updates.
