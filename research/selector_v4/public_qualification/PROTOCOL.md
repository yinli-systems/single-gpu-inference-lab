# Draft public-path qualification 4.3.0

This is a prospective implementation draft. No production manifest, formal
source bundle, stage ticket or fresh GPU dispatch has been created. The original
v4.2 campaign remains dual HOLD, its10 canaries consumed. The original48 release
and12 stress cases remain untouched. Defaults and serving promotion remain OFF.

## Exact sources and prerequisites

Use ordinary independently built FlashInfer packages, presently candidate
75544a17 and pristine85744da1, with normal package version0.7.1 and real build
metadata. No fake feature-off pristine, version replacement or patched native
factory is allowed. Native package files, the344213-byte prefill source prefix,

per-process JIT roots and one physicalGPU/identical allocated CPU affinity for all

winner, window, plan, log, source check and failure survives.

Before freezing the new manifest, the complete existing two-exposed-case public
development prerequisite must pass on bothGPU types with all nine phases,
independent SASS and strict complete-data analysis. A prerequisite PASS allows
manifest preparation only. Its diagnostic receipt has no formal stage authority.
The new source bundle needs its own validated formal smoke and exposed dev
tickets. The formal stage order is smoke→dev2→new10 canary→original48 release→
original12 stress. Every predecessor must pass on bothGPU types with the same
source bundle and manifest. No HTTP performance qualification starts before all
kernel stages pass.

## Measurement and selection

The draft copies the already frozen public development recipe explicitly, then
changes only stage routing, provenance, scope and authorization. Three independent
pristine, three training and three policy processes run sequentially on the same
physicalGPU. Process order is pristine0/train0/train1/pristine1/pristine2/train2/
policy0/policy1/policy2. Every process uses24 balanced blocks with384ms target,
120ms minimum scored windows, fixed30s Native-only conditioning, no trimming,
no adaptive scored-window resampling and20k bootstrap draws.

Eager includes actual native planning and either originalNative.run or public
same-geometry rebind plus real managed-v2.run. A frozen Native choice calls the
original Native path directly. Graph1/16 measure actual captured selected replay,
with unchanged metadata; they do not qualify a full graph-serving step. Source
audits, constructor/compilation, confidence calibration and real managed tuning
occur before scoring, never on a policy cache miss. Every Native winner remains
recorded. Managed profiling_repeat256 is an explicit frozen measurement choice,
not an explanation or repair of the historical12ms profiling outliers.

For held-out policy process i, train(i+1)%3 is the fixed primary artifact and
train(i+2)%3 the secondary. Both must have real accepted certificates, actual
managed Resource winners, exact full outputs/LSE and valid resource bindings.
Their48 complete full-call blocks require geomean≥1.05,95%LCB≥1.01, block
minimum≥.99 and90% duplicate controls within reciprocal±.5%. Any rejection
chooses Native. Source selection is not the fastest observed process. Frozen
choices are persisted before policy scoring. Held-out oracle evidence never
trains or changes the choice.

## Blocking safety and reported regret

Require full output/LSE and Native-after-Resource exactness, complete process and
binary evidence, stable active clocks, nonempty selection in both dtypes/layouts
and all three execution modes, selected geomean≥1.05, selected point/block/joint
minimum95%LCB≥.99, whole-policy point worst≥.99, independent Native/pristine
point worst and joint minimumLCB≥.99, actual policy/pristine point worst and
joint minimumLCB≥.99, and resolved held-out duplicate controls within reciprocal
±1%. Every original.99 floor remains. No failed canary is relabeled fresh.

Report P50/P90/P99/worst and>1% counts of chosen latency relative to the fastest
available held-out certified tactic. The observed policy is also an available
tactic, so regret is nonnegative. This is an available-tactic oracle: an
inconclusive Resource certificate cannot establish unconstrained Resource oracle
performance. P99<1% is the optimization target; it does not replace safety gates
or justify retrying a frozen Native winner.

## Freshness and integrity

Generate only10 replacements for consumed canaries. Preserve original exposed
dev, release and stress cases verbatim, including their stage hashes. Deduplicate
q/cached pairs and each component against all recorded historical manifests,
including renamed sibling/old-manifest files and their original hash ledger.
Record each fresh case as consumed at dispatch intent before the first GPU
submission, including uncertain/failed submissions and executions that later fail. A manifest freeze alone consumes no case.

The dispatcher publishes a ticket after verifying both predecessor verdicts and
their complete raw ledgers. Each process verifies immutable ticket/source/manifest
and predecessor-summary links, not repeated scans of all previous raw data.
Hash changes, missing controls, old diagnostic scopes and incorrect stage routes
block execution. The finite launcher time budget must be set at initial dispatch;
the cluster denied changing the earlier running8h jobs. No samples may be removed
to fit a time budget.

## Full serving is separate

Use the complete model with ordinary radix caching, continuous batching and mixed
traffic. Every source, actual operator geometry, real selected dispatch, model
weights/tokenizer, physicalGPU, request, timeout and failure needs its own binding.
Frozen prepared eager leases may bind once after scheduler metadata update and
before model computation, then serve all layers. Unknown/inconclusive keys stay
Native. Graph/tracing remains Native until a separate graph-metadata resource
contract is implemented and qualified; never reuse an eager receipt for it.

For performance, all five workloads'40 throughput/goodput/TTFT/TPOT metrics enter
the new metric gate, with favorable point ratios and simultaneous allocation-
bootstrap95%LCB≥.99. Throughput improvements cannot hide latency-tail or goodput
regressions. Real metadata/input updates and complete serving-step costs are
included, with independent profiling outside timed blocks. Measure deterministic
full token/logprob parity separately. The historical2/432 token differences remain
unreplicated and unattributed; later112 exact Native tokens and432 exact isolated
Resource calls do not close that failure. The two upstream PRs remain the final
step after qualification; no PR is created by this draft.

## Finite execution draft

`pack_harness.py` archives committed research blobs, rejects uncommitted or
untracked research source, and adds a file-by-file commit provenance ledger.
`pipeline.py --initialize` validates the complete archived prerequisite and normal
packages before formal jobs; no invocation or manifest freeze has occurred yet.
It freezes source and new10 once, retaining original48/12. Initialization requires
current consumption state to match the committed source bundle.

The sole exclusive controller performs fresh dual ninety-test smoke, example,
all three managed modes and SASS checks. It publishes dev authorization, then
advances only through complete dual stage verdicts. At most eight case allocations
are in flight. Each case receives twelve hours at initial sbatch submission;
the controller has a finite fourteen-day deadline. There is no automatic retry
or resampling. On failure it retains the controller traceback, submitted jobs,
conservative dispatch-intent consumption, and all partial measurements. Remaining
allocations can finish under their original limits; successors are blocked.
Successful kernel completion still requires separate full HTTP qualification
and historical token-divergence closure before any default promotion.
