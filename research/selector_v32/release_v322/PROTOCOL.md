# Selector v3.2.2 fresh release qualification

The selector expression, measurement code, overlays, manifest and thirty release geometries are unchanged from v3.2.1. Historical canary verdicts remain HOLD. This qualification revision was frozen only after a separate exposed-case causal diagnosis showed that the old absolute whole-policy canary failures did not reproduce in the deployment-matched independent-runtime paired path.

Primary safety is same-process, same-binary off/guarded pairing. Release requires exact full output/LSE, pristine/off binary transparency, selected absolute and paired safety, unselected paired safety, whole-policy paired point worst and simultaneous joint-min 95% LCB >=0.99, and Graph16 selected aggregate lower bound >1. Absolute pristine/guarded whole-policy is retained as audit-only and cannot be advertised as passing.

Authorization requires both raw canaries to retain their old HOLD, exact numerics and selected signal; both completed diagnosis matrices must contain8640 non-injected windows,15 positive controls,15 qualified case-repeats, zero fallback graph-metadata mismatches, and point worst >=0.995 with per-cell conditional 95% lower bounds >=0.985 in independent pooled-event, independent wall-only and pooled same-graph-null comparisons. This exposed diagnosis only authorizes use of the untouched holdout; the fresh release itself retains the stronger joint-min lower-bound >=0.99 gate.

The release set is split into ten deterministic modulo shards of three cases. Each shard runs three fresh processes, eight ABBA/BAAB blocks, pristine/off/cap/guarded, eager/Graph1/Graph16, ragged/paged, FP16/BF16 and auto/unsplit. Arrays are concurrency-capped; every failure remains evidence. No selector or gate may be adjusted after any release shard begins while calling the same data fresh. Passing is conditional on these two physical GPU families and does not close the historical2/432 full-model token divergence or authorize default/full-serving promotion.
