# Real HTTP cleanup-specific validation

Original pristine FlashInfer and unchanged model weights in both arms. Compare original
SGLang create_abort_task with the source-bound ownership proposal, in separate server
processes on one assigned GPU. Deterministic mode is used in both to make single-request
responses long enough to expose the documented two-second cleanup interval.

Two predeclared epochs of two sequential reused-RID requests, then four unique-RID controls.
The recorder saves every SSE frame, including abort finish reasons. It continues this fixed
negative-control matrix despite expected truncation; no failed request is called successful.
Tokenizer state registration and actual abort target identity are recorded by test-only
wrappers. This can establish stale cleanup of a replacement state, not fix complete-length
token mismatches or measure performance. External diagnostics may change timing.

One GPU,25-minute bound,two servers. No modifications to shared packages or credentials.
No automatic retry. Full production, batch-parallel sampling and multi-worker coverage are
not established by this narrow reproduction. Related PR38850 acknowledged separately.
