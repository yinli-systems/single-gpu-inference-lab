# Scoped full-engine qualification after the direct reuse gate

Registered after direct reuse results were frozen, before any new paged/full-model results. Only RTX4090 /512MiB scratch passed the primary direct reuse gate against both stock and TRAIN-fixed controls. RTX5090 and128MiB are not promoted. No evidence that the following port is numerically or operationally correct exists at registration.

## New boundary, not a silent transfer
Existing runtime archive has vLLM0.29.0,FlashInfer0.6.18,PyTorch2.13.0,Python3.13. Existing cached model Qwen3-4B-Instruct-2507 has36layers,32query/8KVheads,D128. Use convertedFP16 model and KV,TP1,enforce_eager=True; do not claim BF16/graph parity. Explicit FlashInfer prefill and paged cache differ from the prior ragged experiment. Preserve that distinction and pin all sources. No new download of weights, purchase or shared-runtime edit.

Use an isolated process-local adapter around the existing paged wrapper's public plan. Compute actual q lengths and totalKV from page-indptr/page-last-len (cached depth=totalKV-q), preserve page identities in the materialized plan, and always call native plan on each vLLM metadata build. Only decision choices may use a bounded256-entryLRU; never reuse a materialized plan across different page addresses. The engine's own cross-layer plan reuse remains unchanged for every arm. All methods receive identical512MiB workspace and fixed2048GPUKVblocks of16tokens, same request order, model, prompts, decoding and resources.

Frozen native-cycle weights unchanged. TRAIN-fixed arm uses the already selected4090/32head/512MiB/36reuse policy from the successful canary TRAIN_fixed.json. Stock arm uses existing auto. All controls use the same adapter/metadata validation and cache opportunities; report adapter overhead scope. Ragged fixed split tokens must be converted to pages only if exactly divisible. Verify actual public planner scratch allocation; an allocator-identified workspace failure falls back to stock with the failed planning cost charged, never silently allocating more. Other errors terminate qualification. Unsupported head,dtype,mask,graph or configuration uses stock and is counted, not represented as optimized.

## First gate: actual paged outputs
Construct real pagedKV with randomized physical page indices, bothNHD/HND layouts, page16, three changing geometries A/B/C/A,36 distinct layer tensors, and auto/fixed/native_cycle arms. Verify every layer/transition output against stock; selectedFP32reference vectors on representative layers. Include a physical-page permutation with unchanged logical lengths to test that only the policy cache hits while the materialized plan is refreshed. Check workspace ceiling, native-policy identity and fallback counters. No full-engine performance campaign proceeds if this fails.

## Bounded real-model screen
Run the complete model with existing vLLMEngine (not a stand-in MLP). Two finite workloads: (a)8requests, prompt lengths512/1024/2048/4096 repeated,96outputtokens, all admitted atstart; (b)12requests mixing256/1024/4096/8192prompttokens and48/96outputtokens, admitted deterministically over a fixed schedule. Freeze numeric token IDs,seed20261020,temperature0,ignore_eos; avoid tokenizer/network timing. Chunk budget1024, max32sequences. Warmup separately, then record every engine step and request's first/final token observations. TTFT=first output-admission; TPOT=(final-first)/(tokens-1). Throughput includes completion of every planned request. All prompt creation is offline and identical; no timing-dependent workload selection.

Compare auto,fixed,native_cycle in randomized/reversed process order, three process repetitions if capability/correctness screen passes. Primary resource comparison is identical fixedKVcapacity andscratch; also report genuine512MiB demand versus128MiB prior boundary. Report p50/p95/p99requestlatency,TTFT/TPOT,completionrate and predeterminedSLOgoodput (TTFT<=2s AND TPOT<=50ms; supplementary lenient5s/100ms). No dropping failed/timed-out requests. Exact greedytokenmatch is a qualification gate, not assumed; if it fails retain traces and do not promote without a separate prespecified tolerance/quality test.

Admission/first-token metrics come from an in-process engine and are not HTTP/network serving latency. Any engine compatibility failure is a recorded blocker, not a reason to substitute operator timing. Model load/JITexcluded from steady state but separately reported. An initial one-repetition screen may be used solely to qualify interfaces; it does not establish stableSLOgains.

## Evaluation and stop rule
Full-model benefit is accepted only if correctness and complete coverage pass and paired independent process/workload repetitions support a lowerCIbound>1 for throughput without worseningSLOgoodput. Report conditional uncertainty and sparseSLOevents. If no benefit, retain the direct4090attention-stack result but reject full-system promotion. No one-shot prize/SOTA claim.
