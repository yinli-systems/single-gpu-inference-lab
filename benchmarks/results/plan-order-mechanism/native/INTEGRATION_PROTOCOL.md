# Native source integration qualification and cycle pilot

Registered before this native-source pilot. The heavy-first rule is unchanged from measurement commit ad26dac. This follow-up does not replace the 43,200-row confirmatory metadata-order study and does not select a different policy from its results.

Apply a default-off experimental helper at the actual FlashInfer0.6.18 FA2 host planner. Package is an isolated overlay; shared runtime and model weights are untouched. The helper sorts only the request/query-tile/KV-tile triples after planning; output/merge destinations and all plan scalars must match identity. Unknown policy, padded/dynamic graph plans and non-ragged page units are rejected. Source fingerprints bind the patch. Dynamic graph support and a public API are not implemented; the environment flag is for this controlled process only.

Cases: discovery n2/n4 same/opposite plus same-order states of all eight predeclared held-out geometries. FP16/BF16, auto/unsplit, reuse1/36, six randomized blocks after two discarded warm-up blocks. Each family receives one finite15-minute pilot, at most two GPUs total. Identity-repeat is retained. This is only one process per GPU family, so no confirmatory confidence or deployment promotion follows from the pilot.

Every state checks actual compiled-native descriptor hashes against the frozen Python rule, all plan-scalar/protected invariants, full output and LSE bitwise in eager and graph, plus selected FP32 vectors. The pilot times actual plan+graph-replay+completion wall time; metadata copies/sort inside the native plan are charged. Graph capture, warmup and correctness checks are outside both arms' timing. Reuse36 means36 actual attention calls, not a division of a measured CPU cost.

Both arms use the same compiled source. The identity arm includes the disabled environment-check branch, so the pilot is not a pristine upstream-main serving benchmark. All negative rows, A/A controls, startup cost and failures are retained. Main serving promotion remains false. No upstream PR is submitted before this narrower path is qualified.
